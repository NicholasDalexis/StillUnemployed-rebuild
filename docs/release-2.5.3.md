## Preventing repeated mistakes

The same visible version can have different features because host gates and provider settings are separate from source. Production2.5.2 explicitly disabled auth and lacked authorized production domains. Record source/deploy fingerprints plus enabled provider features, rather than treating a version label alone as proof. Apex/www Google configuration was saved and read back; the gate is removed in2.5.3 source.

Synchronous UI renders were tested mainly as isolated actions. A background refresh duplicated Recently viewed; a Saved sync left an open button stale; an account transition exposed stale device history. Integration now renders the modal once, updates existing controls without replacing focused content, and fails closed on stale ownership. Regression tests reproduce the pre-fix failures.

An availability queue initially reused historical signed reporters as current hold authority. A later anonymous UNKNOWN could therefore re-hide an open-restored listing. Current hold authorization is now separate from the historical audit and resets on restoration. Tests cover the full report, restore, anonymous re-report and uncertain-check sequence.

The email path initially treated five known-unsent quota/lock responses like ambiguous dispatch. It now retries confirmed pre-send failures with backoff while holding uncertain sends behind stable deduplication. Concurrent workers and lost receipt writes were tested with the real receiver logic offline; actual inbox delivery is a separate proof.

The Monday script had a distinct zero-quota state that prevented retry after recovery. Its cloud source now matches the reviewed local patch, with the same recipient, manifest and five-minute trigger. A Sunday execution completed without sending mail. The supplied Sunday server error does not establish that a Monday email failed; its exact Google cause remains unknown.
